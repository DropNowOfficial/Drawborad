# Local native stroke correction: controlled desktop preview

## Evidence and chosen direction
A private one-attempt lower-eyelid study was rejected: contour/width rhythm and companion-line spacing did not match the reference. Repeated redraws and random texture are not a remedy. The current desktop can store per-sample pressure and coordinates but lacks a reversible local sample-edit command; mouse taper is only a whole-gesture envelope.

Mature tools demonstrate spatial editing rather than more global brush knobs: [Inkscape's official beginners guide](https://inkscape-manuals.readthedocs.io/en/latest/pencil-tool.html) describes interactive variable-width handles, while [Krita's shape-edit documentation](https://docs.krita.org/en/reference_manual/tools/shape_edit.html) describes local nodes and handles. This change is a deliberately smaller custom implementation, not copied code or a claim to implement those complete systems.

## Implemented core and limits
AdjustStrokeSamples changes only x/y/pressure samples on the global last engine19 solid-ink event, with identical count, timestamps and device/tilt metadata. Color/style/seed/identity and all other events remain untouched. Only a single-operation command on an editable native layer is accepted. Canvas/event/point budgets and finite bounds are independently checked at the command boundary.

localStrokeEditCommand uses original arc-length radius (0,128] pixels around a chosen existing sample, with compact-support smoothstep weighting. Radius is not a sample-count setting; different sampling density does not redefine the local region. Outside samples remain byte-identical. Coincident adjacent samples get the same spatial weight. No interpolation points are added. Coordinate or pressure overflow rejects the whole proposal; no silent clamping. This cannot add missing control nodes, change stroke topology or automatically infer a good contour from an image.

## Desktop and safety acceptance
The desktop explicitly enters correction mode, shows existing sample handles, and selects only a handle within ten logical pixels and inside the viewport. Dragging supplies original-pixel displacement; numeric displacement and pressure delta are also explicit. Zoom/pan use the same canvas transform. Correction mode disables native painting input, while its overlay supports middle-button pan/wheel zoom. It adds no samples and cannot edit sparse-stroke interiors where no sample exists.

A bounded worker applies the proposed command to a temporary snapshot, validates tagged mixed finishing layers, and fully renders the candidate before publishing a preview. The GUI receives a single-slot completion via its timer, checking cancellation, document identity, revision and generation. Accept is explicit; busy/pending blocks save and other mutations. Preview hides the old control handles to avoid showing them against the modified stroke. Cancel changes nothing. Accept updates the original event, NOT a new layer, and remains undoable. Original raster/resource bytes, sample count, timing, device metadata, style and all other events are preserved; deliberately edited pressure is not a claim of physical-tablet measurement.

Release Linux full suite passed **106/106, 24.06 seconds with -j4**; actual offscreen Qt/QML test passed **22.37 seconds** in that run. Coverage includes actual pointer hit after zoom/pan, out-of-view selection rejection, changed candidate pixels, original snapshot unchanged before acceptance, cancellation, blocked saving while pending, exact edited-event pressure/coordinates, Undo/redo, saved/reopened pixel equality, invalid sample/radius/pressure refusal and immediate worker cancellation. Core B40 additionally covers exact outside-arc samples and metadata, differing sample density, duplicate positions, canvas/event budgets and command-boundary rejection. Initial integration test incorrectly compared shared resource-map addresses; corrected to compare original resource bytes, which are unchanged.

These are synthetic functional fixtures and Linux software-rendering tests, not a high-quality artwork delivery, Windows validation or physical-pen validation. No automatic contour inference, missing-detail recovery, full Bezier editor or insertion of new nodes has been implemented. The private rejected study and references remain excluded from uploads. User goal is still not met; report phases truthfully rather than equating a passing feature test with a finished artwork.
