# Opt-in mouse pressure taper, not artificial artwork

The actual native web input assigned pressure1 to every mouse point, although fine/smooth/dry renderers already supported pressure. This causes constant-width rounded mouse strokes. MyPaint already has its own fixed-pressure control; real pen pressure already worked. This change addresses native mouse input only, not those existing features.

The native command accepts optional `pressure_taper` in [0,.5], the fraction of arc length used at EACH end. Web UI defaults Off, with10/20/35% presets. It is captured at pointerdown, applied only for pointerType mouse and only when the engine advertises support. Real pen/touch/MyPaint input remains unchanged. The helper multiplies input pressure by a linear distance envelope from5% at the endpoint to100% in the middle. Centerline positions are retained. Two ramp-boundary points are interpolated when needed so a two-point stroke remains visible; dots/zero-length strokes are unchanged. Ramps cannot consume more than half each, so short strokes retain peak pressure. This is simulated assistance, not physical pressure or wet pigment.

Browser sampling exposed a real coverage limitation: redundant collinear segments can create extra round caps. Taper preprocessing removes ONLY geometric and pressure-linear redundancy within1e-9 tolerance, without moving the path. This is not general smoothing or resampling; corners and non-linear pressure remain. A same-centerline two-point and17-point mouse line now produces identical pixels. Default-off strokes and all old saved events bypass the helper. Existing engine10/12/19 serialized pressure stores the actual result, so save/reopen does not depend on current UI settings and no new format is introduced.

Validation: missing-feature headless and actual pointer-handler tests failed before implementation. Tests cover narrow endpoints/full center, sparse/dense equality, Off equality, clicks, invalid parameters/state invariance, pointerdown setting snapshot, true pen preservation, old-engine guard, and native save/reopen. Full suite results are reported separately. Web/API/native command integration only: desktop Qt mouse input is NOT yet wired to this new assistance. The temporary blue guide still shows the path, not final pressure width; release shows the native result.

This improves a specific line-control deficit. It cannot reconstruct reference details, choose artistic contours, make rich natural hatching or produce a world-class painting. No replacement artwork is an acceptance criterion or deliverable for this feature. No random texture, image model or private source material is included.

Completion evidence:92/92 local CTest;72/72 cloud Python tests and23subtests. Added independent core cases for50% coincident knots, short lines, corners, reversals,1024-input limit and stationary dots. Independent code review found no blocking issue. A native81-point arc diagnostic was visually reviewed: rounded equal-width ends are replaced by continuous tapered ends with the middle width retained. It still looks like a regular symmetric arc; the reviewer explicitly rejected inferring human-art quality from this. The diagnostic is a tool check, not a replacement artwork. No private reference or image is committed.
