## 1. 产品契约与本次变更

交付面向用户长期使用、并为未来商业发行保留边界的 Windows 11 桌面软件。核心流程是：导入自定义图片 → 自动提出对象分层 → 人工复核 → 分区重绘 → 局部精修 → 原生工程与 PSD/PNG 等多格式交付。绘画回放是作品的一个可检查视图，不再控制整个编辑器。

用户最新选择覆盖先前建议：

- 保真、对象可编辑性、自然绘制过程同时达标；不将任何一项降为可以牺牲的装饰项。
- 完整安装后无需联网。标准安装交付包含受支持核心模型、运行库和资源；模型管理通过本地包进行。
- CMYK 是首版真实文档模式，不只是导出时改变标签；同时保留 sRGB、Display P3、Adobe RGB 与自定义 ICC。
- 允许自定义尺寸、比例、单位和分辨率，不能只给固定模板。
- 支持 PSB 导入，但不交付 PSB 导出；不能把这两个选择混成“不支持 PSB”。
- UI 采用 Apple 式完整交互与视觉语言，在 Windows 11 上使用原生窗口和输入习惯；精简工作区与专业检查器共存。
- 第 14 项未回答：暂按上一轮推荐 A（完整人工修层工具）列入范围，明确为待随本文审阅确认的默认项。

需求逐项映射见 ../../product/requirements-2026-10-04.md。视觉与验收细则见 ../../product/apple-experience-and-acceptance.md。

### 不得重复的失败

不得默认装入简笔画模板冒充高质量作品；不得将八张图片淡入淡出、用大软刷揭示整张成图或在章节结尾换照片；不得让随机抖动改变文字、Logo、轮廓；不得用“100% 时间轴”代替实际完成；不得以可运行界面代替 PSD 互通和 Windows 真机测试。

参考图只用于显式参考/分析。重绘完成层必须来自可记录的笔刷、区域构造和校正事件，不允许隐藏原图兜底。用户明确导入原图为普通像素层时，应标注其来源，并与重绘模式分开。

单张合成图无法唯一确定原始图层和真实作画历史。软件产出的是重建的对象、可解释的笔迹与蒙版，不声称恢复原作者记录。被遮挡的内容默认透明/未观察，不自动编造。任何后续推测补全必须主动启用、独立标记。

## 2. 架构比较与推荐

| 方案 | 收益 | 代价 | 本项目决定 |
| --- | --- | --- | --- |
| C++20 + Qt 6/QML + 原生分块画布 | 编辑器、数位笔、ICC、后台处理具有清楚边界；不依赖网页 Canvas 重绘 | 原生编译与部署测试成本较高 | 推荐架构 |
| Tauri + Rust 核心 + WebView UI | 可复用部分网页交互，安装体积可以控制 | 双栈与跨边界数据搬运；保留旧 Canvas 不能解决卡顿 | 备选，不作为首选 |
| Electron 网页封装 | 原型迁移快 | 原来的重放、全层复制与高内存路径仍需改写 | 不作为正式架构 |

采用 C++20 文档/渲染核心、Qt Quick 界面和原生画布项。Windows 图形基线优先 Direct3D 11，经目标机验证后再决定是否开放 D3D12 选项；CUDA 属于推理后端，不是 UI 后端。[S1][S2] 不使用 QML Canvas/JavaScript 数十万循环作为画面核心。

Qt、编译器、ONNX Runtime、CUDA/cuDNN、色彩库、编解码器必须锁定到通过兼容测试的完整版本组合；不能使用浮动 latest。在实施计划的构建依赖清单中固定确切补丁号和校验值，未验证的库组合不能进入安装包。[S3]

### 子系统边界

1. Document Core：对象、图层、蒙版、颜色空间、笔迹与命令；不依赖 QML。
2. Tile Renderer：只消费文档快照，生成被修改区域的颜色数据、显示纹理与缩放层级。
3. Reconstruction Worker：独立可终止进程；模型分析、候选蒙版、局部重绘、质量报告。
4. Color Service：ICC 赋予/转换、CMYK 原生通道、显示转换、软打样和导出转换。
5. Persistence：事务日志、内容寻址块、版本检查点和原子保存。
6. Codec Worker：不可信文件解析与 PSD/TIFF 等导出；不阻塞 UI，不直接改活动工程。
7. Shell/UI：工作区、面板、命令、任务反馈、中英文本、Windows Ink 事件。

主流程：输入解码与 ICC 预检 → 只读原图资源 → 候选对象/蒙版 → 用户复核快照 → 后台生成局部笔迹 → 原子提交新版本 → 缓存/显示 → 导出。

## 3. 核心体验与工作流

### 3.1 导入与预检

支持 PNG、JPEG、WebP、TIFF、BMP、PSD、PSB。HEIC 是可选离线编解码模块；没有模块时明确说明，不触发在线商店或联网安装。输入格式支持不等同于支持所有稀有子格式：遇到未知位深、压缩、色彩模式或损坏结构，返回可解释错误，保持原文件不变。

显示尺寸、位深、颜色空间、ICC、透明度、内存/磁盘估计。分析可以使用缩略层级，但最终重绘、蒙版边缘和导出仍在文档分辨率上处理；不能静默缩小再放大。

PSD/PSB 已有对象组、像素层、蒙版、透明度、常用混合模式应保留。可编辑文字、智能对象、调整层和特殊效果不在首版完整编辑范围；先列出不支持项，由用户选择显式栅格化到副本、使用文件内已有合成预览作为新输入，或取消。没有可靠预览时拒绝错误的“成功导入”。PSB 大尺寸必须预检，支持解析不等于任意大图都可实时使用。[S4]

### 3.2 Review：自动分层不是不可撤销结论

先给对象候选和置信提示；点选/框选提示修正、加减蒙版、画笔修边、羽化、扩张/收缩、去杂边、移动缩放、合并与拆分均纳入首版。低置信区域明确显示，但不杜撰概率数字。

对象蒙版覆盖不足、对象重叠和透明边缘在重绘前可检查。一键接受建议可用；默认不自动越过 Review。用户在批处理设置中明确授权接受建议后才可无人值守。

### 3.3 两个维度而不是一个八层模板

对象组如背景、产品、Logo、文字、头发、服装、投影；每组包含按需要创建的 base/shadow/texture/highlight 子层。并非每个对象必须机械地生成四层。图层拥有稳定 ID、独立蒙版、变换、可见性、锁定、透明度、混合模式与颜色配置引用。

时间轴由有序事件构成：事件引用对象、图层、工具、颜色空间、区域边界、路径/压力/速度、随机种子、父文档版本和工具版本。对象图层重排不改变历史事件身份。回放明确显示是在查看当前编辑结果还是原重建版本。

### 3.4 保真重绘与自然笔法

多尺度生成从大形、连续轮廓、受约束的局部底色到细节；根据重建误差细化，而不是全画面撒随机短线。文字和 Logo 默认按实际可见形状重建，不用字体替身或提示词重新生成。可选文字识别只在用户主动请求、且图像形状路线不能满足编辑需求时进行；展示识别候选与缺失字体，不自动替换源形状。

笔迹在语义局部排序，完成一个连贯区域再转移。铅笔、马克笔、彩铅、高光拥有各自的笔压和覆盖规律；随机值由已存种子决定，渲染时不可重新取随机数。抗锯齿接缝、局部蒙版边缘、透明反光要显式校正。校正仍记录为局部工具操作，不使用整张残差照片作为“最终细节层”。

Fidelity、Dry Media、Marker、Pencil、Concept Sketch 共享对象结构与历史索引。Fidelity 不主动风格化；风格模式的预期偏离单独展示，不能把风格模式的低保真当 Fidelity 验收通过。

如果保真、分层或自然过程任一项不达标，报告未通过的区域和原因，让用户修层或增加局部质量预算；不为了流畅假装最终完成。自然过程是合成示范，不伪称真人录像。

### 3.5 精修与回放

鼠标/数位笔都可以直接编辑对象、图层和蒙版；Windows Ink 与设备可提供的笔压、倾角、笔尾/橡皮擦输入进入标准事件。设备未报告的值使用明确固定回退，不伪造硬件支持。原始采样和确定性的重采样结果均可用于诊断。

笔刷、图层拖动、蒙版拖动 1:1 跟随输入，不加入弹簧延迟。编辑完成一个事务后只提交受影响的块。新增输入优先级高于后台重绘。

回放支持暂停、逐笔/逐组步进、速度、循环区域、任意定位、只看新增、局部放大。当前事件和进度对应真实完成数量。回退到最近的有效检查点，只执行索引区间；检查点是由本软件事件生成的缓存，损坏或不存在时可丢弃并重建。首帧白纸；任何阶段边界不替换输入图片。

## 4. 原生画布、内存与性能

目标硬件（用户提供，尚未本机实测）：Core Ultra 9 185H、32 GB 内存、RTX 4070 Laptop 8 GB、Windows 11 x64；驱动版本记录为 32.0.15.9636。Intel Arc/NPU 不承担首版核心计算。

512×512 为初始块尺寸。坐标、包围盒、像素总量和偏移使用带溢出检查的整数；颜色块采用明确通道布局。空块不分配，活动块内存缓存，冷块压缩后落盘。CPU RGBA/CMYKA 权威数据与 GPU 显示纹理分开，颜色空间、DPI、GPU 资源寿命不混入对象坐标。

缓存键包含 documentRevision、layerRevision、maskRevision、transform、profile/intent、renderEngineVersion、scaleLevel、tilePosition。蒙版、透明度、ICC 或图层顺序改变时仅失效受影响依赖；不触发全事件重放。缩放平移优先使用已有纹理层级，空闲时细化。

常规内存目标 8–12 GiB，18 GiB 为主动回收软线；超过可用预算安全降并发或暂停，绝不使用导致全机失去响应的无界分配。常规 GPU 画布缓存目标不超过 2 GiB；推理与显示共享约 6 GiB 的应用软预算，以实时剩余显存为准，并不把 ONNX 的单内存池参数误当设备总上限。[S3] 只允许一个重 GPU 推理任务，队列可取消。CPU 并发先以留出交互线程的保守配置启动，再基准调优。

4K 明确定义为最多 4096×4096 的核心验收尺寸，64 个可见内容层为正常工作档，128 层为压力档。8K（最多 8192×8192）允许后台细化与长导出，不承诺与 4K 同速。百万级笔迹在编辑路径上不逐笔扫描。

GPU 超时/设备丢失只丢失可重建缓存。Worker 返回 jobId、输入 revision、输出哈希、取消状态；过时结果不得覆盖新编辑。取消先即时确认，随后按安全点终止；超时则终止独立 worker 并清理临时输出。

## 5. 真 CMYK、ICC 和自由尺寸

### 5.1 文档颜色

首版文档像素模式定义为 RGB(A) 或 CMYK(A)，每色通道 8/16-bit；ICC 内嵌或明确指定。原生颜色数据不能把 CMYK 偷换成 RGB 后只保留文件名。C/M/Y/K 单通道读数、可见性、笔刷颜色输入、蒙版与图层编辑都须可检查。Alpha/蒙版独立于四个油墨通道。

Little CMS 2 是候选 ICC 核心，支持颜色配置转换、软打样等能力；实际版本和性能需验证。[S5] QML 的颜色值仅属于界面/显示，不作为 CMYK 文档存储。

Assign Profile 只改变解释，Convert Profile 才改变像素，操作必须分开。未标记 RGB 可提示使用 sRGB；未标记 CMYK 必须让用户选择已有/自带 ICC，不能宣称“通用 CMYK”。提供合法可再分发的常用 CMYK 配置，用户可离线导入 ICC。色彩转换保存意图、黑点补偿、配置哈希。

分割模型接收由 ICC 转换生成的 RGB 分析视图，但不改权威 CMYK 数据。显示采用文档 ICC → 显示器 ICC；软打样增加目标印刷配置、纸白模拟和色域警告。屏幕预览不能许诺所有打印机绝对一致。

首批通用混合模式为 Normal、Multiply、Screen、Darken、Lighten；RGB/CMYK 每种都必须通过对应 Photoshop 样例。像 Overlay 等追加模式需单独标为未验证或禁用，不能悄悄用近似算法替代。高精度中间计算避免累计舍入；颜色转换是明确命令，不逐帧往返损坏原数据。

### 5.2 新建与尺寸

允许用户自由输入宽/高、解锁比例、px/mm/cm/in、PPI、方向、RGB/CMYK、8/16-bit、ICC、背景透明/指定纸色。预设是快捷方式，不是唯一尺寸入口。物理尺寸通过明确 PPI 换算，显示舍入后的实际像素数；只改 PPI 元数据与重新采样分开。

“自由”不代表无限内存或绕过文件格式边界。任何正尺寸输入都先检查范围、乘法溢出、目标像素量、块数、内存/暂存盘和编码器限制；超预算必须在分配前明确拒绝或让用户选择较小尺寸/分块交付，禁止静默缩图。4K/8K 是测试包络，不是将画幅限制为几个比例。

PSD 的文档上限和大小约束与原生工程不同；超过可支持 PSD 输出边界时不能静默切成 PSB，按用户选择提示改尺寸、分块或保留原生工程。[S4][S6]

## 6. 模型与完全离线交付

标准完整安装包包含通过本机兼容测试的标准模型及随版本提供的高质量模型、CPU/CUDA 推理运行库、所需可再分发资源和本地说明。不可使用要求首次在线下载的启动器，也不可在首次运行执行 pip/npm 等在线安装。允许大安装包以多个离线校验文件分卷，但需从本地一键装完。未验证的额外模型不打着“高质量包”进入发行版。

SAM 2.1 Tiny/Small 是对象蒙版候选，需测试转换后的 ONNX 与官方输出一致性；它们不自动理解所有对象名称，也不自动生成自然绘画步骤。[S7] 不以模型参数量代替峰值显存或处理时间实测。不能合规打包或质量不达标的模型替换候选，不能要求用户用联网服务补齐核心功能。

Model Manager 支持本地导入/导出/卸载、标准/高质量档、自定义模型选择、禁用、查看哈希与许可、兼容性测试。首版自定义包以 ONNX 数据模型和版本化声明式 manifest 为执行契约：任务类型、输入输出张量、预处理、后处理、动态尺寸、provider、runtime ABI、权重哈希、预计预算、许可与来源。仅已实现的 task adapter 可用；不声称任意模型文件都能运行。

不得从模型包执行任意 Python、pickle、DLL、自定义算子或外部命令。未经信任签名的用户包必须显式确认并通过隔离验证；签名可信也不免除形状、文件路径、解压和资源限制检查。safetensors 不是独立架构定义，不能仅因后缀安全就自动执行。新增架构适配属于后续明确开发，不等于首版开放插件系统。

模型、自定义包和用户素材不上传 GitHub。开发中可联网获取已审核依赖，最终用户运行无联网要求。应用默认没有遥测、自动更新、云端 fallback 或网络许可检查；更新采用用户选择的离线安装包。操作系统自身服务的行为不伪称由本软件控制。

## 7. 工程、撤销、恢复与复现

工程含稳定英文 schema、对象/图层 DAG、原始可见区域来源说明、ICC 原文件、蒙版块、笔迹二进制、工具版本、参数、种子、模型哈希与必要中间结果。输入图片可作为明确只读参考资源保存，但任何重绘图层不能通过引用该图片直接完成渲染。

编辑期间使用单写者事务日志与内容寻址块；工程快照和 journal 原子提交。保存为自包含原生归档，采用临时写入、完整性验证、原子替换与上一个有效版本；不覆盖正在使用或不可写文件。崩溃后从最近有效快照和已提交命令恢复，损坏尾部隔离报告。

Undo/Redo 是可验证命令事务，包含图层改名、移动、蒙版、重绘提交、ICC 转换，而非只有最后一笔。局部 checkpoints 有可配置磁盘预算和保护点；清理前保留当前有效工程。队列取消不能提交半成品到正式工程。

复现分两层：同一已存工程在锁定 CPU 参考渲染器中应产生相同规范化像素哈希；不同 GPU 驱动显示预览允许量化容差但必须记录。再次运行 AI 分析与重新打开已存工程不同，不仅凭 seed 承诺跨平台/跨版本一致。[S8]

所有导入路径防止 zip-slip、递归包、解压炸弹和不受控内存分配；外部模型/PSD/TIFF 解析放入可终止进程。网络内容不成为代码指令。构建产物、项目缓存、真实客户图和模型权重不直接推入普通 Git 历史。

| PSD | 像素层、对象组、蒙版、透明度、已验证混合模式 | 是，8/16-bit | 是，8/16-bit | ICC、四油墨通道及合成图实际写入；不伪造文字/智能对象 |
| PNG | 合成或单层透明导出 | 是，8/16-bit | 否 | CMYK 必须显式转换到选择的 RGB ICC |
| TIFF | 首版合成/单层；完整编辑结构交付 PSD/原生 | 是，8/16-bit | 是，8/16-bit | ICC、位深、压缩选项明示 |
| JPEG | 扁平合成 | 是 | 可选、需互通验证 | 无 alpha；指定底色；CMYK 不作为网页通用默认 |
| WebP | 合成或单层 alpha | 是，8-bit | 否 | 显式颜色/位深转换 |
| ORA | 标准可兼容像素层 | 是 | 不直接保留 | CMYK 经明确 RGB 转换；不能说 ORA 无损保存原 CMYK |
| 图层 PNG ZIP | 逐层透明图与 manifest | 是 | PNG 本身否 | 尺寸/偏移/名称/配置和转换记录齐全 |
| PSB | 不提供导出 | — | — | 保留 PSB 输入能力，超 PSD 输出限制给明确替代方案 |

所有导出提供预检、路径/文件名、配置、位深、尺寸、估计文件大小、覆盖确认和取消。文本候选不等于 PSD 文字层；首版输出忠实像素层。对不支持的源功能先列转换清单，不自动压平所有内容。

默认保留必要 ICC/尺寸信息，不主动传播 GPS/相机隐私字段；EXIF/XMP 保留是显式选项。渲染器不添加品牌水印或调用图片生成 API，也不保证清除源图中已嵌入的可见/不可见标记，不伪造内容来源声明。
