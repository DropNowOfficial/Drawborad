# Connected contour desktop stage (local acceptance)

Goal: let a person deliberately shape a two-sided contour before region coloring, without replacing the original artwork or flattening editable geometry. This is a drawing tool improvement, not faithful automatic reconstruction or a finished work.

New contours begin as two explicitly closed cubic spans with six stored points. Anchors are shared, not duplicated endpoint copies. All six draft points can be adjusted before an atomic creation. Existing engine-24 paths retain their exact open/closed topology and control count: each edit transaction adjusts only one point. A second point cannot silently replace the first edit. Accept or discard, then begin another point edit. Returning the selected point exactly to its original position can release the single-point restriction.

The older engine-23 four-control tool and replay remain separate. No existing stroke is silently converted. Guide lines show control geometry; the asynchronously rendered preview is the actual nib result. A closed guide is not proof of safe bucket filling, and a plain document is not silently converted into a controlled lineart project. Existing derived-fill dependency protection can reject later contour editing; automatic fill reflow is not implemented.

Locally exercised acceptance: real QML pointer actions; shared-anchor motion; selected-point refusal without loss; resume preview with all values intact; cancel and stale completion isolation; resize/ungrab/outside/focus-loss restoration; Undo; native save and reopen; retained format23 behavior; no false busy spinner; no Binding loop/ReferenceError/TypeError diagnostics. Release build completed and all 122 tests passed in 89.96 seconds. Qt path controls took 2.42 seconds, path bridge 0.19 seconds; old 23 controls/bridge and the complete Qt canvas suite also passed. Full-test and final screenshot logs contain zero Binding loop, ReferenceError or TypeError diagnostics. Actual six-control preview and second-point-refusal screenshots show the relevant local action and complete refusal text. These are synthetic tool demonstrations, not new artworks. Final hashes and remote publication status belong in the sealed stage receipt.

Linux cloud Qt testing does not qualify Windows hardware, physical pen input, native image detail, CMYK, physical print color, or artistic quality. Synthetic operation demonstrations must be labeled as technical examples, not new artwork.

UI scope: creation exposes two-span closed contours only. Existing open paths can be read and edited without changing topology. This stage's dedicated interactive tests cover the two-span closed and seven-control open examples, not maximum eight-span interactions or injected low-memory preview failures.
